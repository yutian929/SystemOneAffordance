# 最小 Affordance 决策测试

创建日期：2026-10-15。本文保留初始实验方案；截至 2026-10-17，A、D 已完成首轮调试运行。D 的当前实现、运行结果与改进讨论见 [05](05_method_d_analysis_and_improvements.md)。

我们先验证：**输入图像与指令，视觉 System One 模型能否通过区域选择或前后景判断，得到正确的交互区域 mask？**

目前保留 **A：区域独立判断**、**C：随机点判断** 和新增的 **D：掩码连通域中心点判断**，计划使用预训练模型做离线、零样本比较。B 保留原方案说明，但单选版标记为 PASS，不纳入实验。模型、候选数和采样点数都是初始设置。

## 四种形式与当前取舍

| 方式 | 输入给决策模型什么 | 模型输出 | 最终 mask 怎样得到 |
| --- | --- | --- | --- |
| A：逐个高亮区域 | 全图分割后，每次在完整原图中高亮一个候选，加上指令 | 每个候选的独立 Noul 分数 | 保留所有达到阈值的候选，将其原始 mask 取并集 |
| B：全部编号后单选（PASS） | 全图分割后，在同一张图上标出全部候选及编号，加上指令 | 一个候选编号或“都不合适” | 取对应的单个 mask；无法同时选取多个有效候选 |
| C：随机点判断 | 在完整原图的随机位置逐次标点，加上指令 | 每个点属于目标前景的 Noul 分数 | 对各预测前景点分别提示 SAM，再将得到的 mask 取并集 |
| D：连通域中心点判断 | 全图分割后，取各候选 mask 的每个连通域中心点，逐次在完整原图上标点，加上指令 | 每个点属于目标前景的 Noul 分数 | 沿用 C 的点提示分割与合并流程 |

A、B、D 的“全图分割”指自动生成一组候选 mask；它们可能重叠或嵌套，并不要求形成互斥的语义分区。C 从随机采样点开始；D 则用分割得到的区域结构选点，再进行与 C 相同的点判断。

首版统一使用 **Valen-4B + SAM 2.1 small**：决策模型为 `Valen-Team/Valen-4B`，用于 A、C、D 的 Noul 二分类判断；SAM 为 A、D 生成自动候选，为 C、D 接收点提示。三种保留方案均输出与原图同尺寸的二值 mask，并保留合并前的各个 mask。[SAM 2 官方仓库](https://github.com/facebookresearch/sam2)、[Valen 仓库](https://github.com/Liuziyu77/Valen)、[Valen-4B 模型卡](https://huggingface.co/Valen-Team/Valen-4B)

**输出应覆盖指令要求的全部有效区域。** “找出所有可以抓握的部位”允许包含多个物体的部位；“抓住左边杯子的杯柄”只包含指定杯柄。一个二值 mask 可以表示多个分离区域，合并后不只保留最大的连通区域。

## A：先分割，逐个高亮判断

```text
原图 → SAM 自动候选 → 逐个高亮 → Noul 独立判断 → 阈值筛选 → 多个候选 mask 取并集
```

候选生成只读取图像，去掉空掩码与高度重复掩码，暂定最多保留 24 个。保存 mask、编号和过滤参数，小部件不能仅因面积小就被全部丢弃。同图不同指令复用该集合。

每次在完整原图上以半透明青色和轮廓标出一个候选，透明度先固定为 0.25。问题示意：

```text
任务：{instruction}
高亮区域是否是这条指令要求的有效交互区域之一？
请独立判断该区域；若只是包含有效部位，却同时覆盖大量无关区域，应回答否。
```

读取每个候选的 Noul true 分数，初始保留所有分数不低于 0.5 的候选，不限制只选一个。将保留的原始 mask 按像素取并集，重叠像素只计一次；同时保存各候选的编号、mask、分数和原始响应。

0.5 只是起始阈值，Noul 分数尚未在 Affordance 上校准。阈值可在调试样本上检查，固定检查集运行前冻结。合并时要观察大区域误选是否带来明显的背景扩张。

有 K 个候选时，首版产生 K 张高亮图并逐个判断。若候选集合为空，或没有候选达到阈值，返回空 mask 并分别记录原因，不强行保留最高分候选。

## B：先分割，全部编号后选择（PASS）

```text
原图 → SAM 自动候选 → 同图展示全部候选及编号 → Choice 单选 → 对应候选 mask
```

候选生成与 A 相同，但将全部候选的轮廓及编号画在一张图上，让模型结合指令一次比较，选择一个编号或“都不合适”。选中编号时返回对应的原始 mask，选择“都不合适”时返回空 mask。

**PASS 原因：原方案只能选一个候选，但指令对应的有效区域可能分布在多个候选中。** 例如“找出所有可以抓握的部位”，多个工具的手柄可能都应保留；单选只能留下其中一个，造成漏检。即使单个 mask 本身可以包含多个连通域，也不能保证它恰好覆盖所有需要的区域。

因此本轮不实现这个单选版 B。限制来自“一次只选一个”的输出设计；编号图以后仍可配合对每个编号的独立二分类，允许同时保留多个候选，当前先不展开。附录的 Choice 保留为通用接口示例。

## C：随机给点，判断前后景后分割

```text
原图 → 随机采样点 → 逐点标记并判断 → 每个预测前景点分别提示 SAM → 多个 mask 取并集
```

先在整张图中均匀随机采样 32 个不重复的像素位置，保存随机种子和原图坐标。同一张图使用固定点集，不根据 GT 或模型结果重新挑点。

首版每次只画一个小空心标记，让标记中心对应待判断像素，尽量保留该位置的视觉细节。完整原图与指令一起输入模型，提问：

```text
任务：{instruction}
标记中心的位置，是否属于这条指令对应的目标交互部位？
```

**这里的前景是指令指定的交互区域。** 例如指令要求抓杯柄，杯柄是前景，杯身、桌面等都可以是背景；判断“这个点是否在杯子上”不够准确。

读取每个点的 Noul true 分数。初始规则固定为：分数不低于 0.5 标为前景，其余标为背景；0.5 只是起始阈值，需要在调试样本上检查，检查集运行前冻结。

为显式支持多个分离区域，首版采用下面的简单流程，效果仍需测试：

1. 给 SAM **未经标记的原始图像**，复用该图的图像特征。
2. 对每个预测前景点分别调用一次 SAM：该点标为前景 1，加上全部预测背景点，标为背景 0。其他预测前景点不参与该次提示。
3. 每次先采用单 mask 输出，将各次结果按像素取并集，同时保存每个点对应的原始 mask。重复区域在并集中只计一次，不只保留最大的区域。

这里允许多区域，来自多次分割后的合并；SAM 的 `multimask_output` 提供同一组提示的多个候选解释，不能直接当作多个目标的实例列表。若没有预测前景点，则返回空 mask、记录该情况，不强行把最高分点当成前景。[SAM 点提示接口](https://github.com/facebookresearch/sam2/blob/main/sam2/sam2_image_predictor.py)

C 需要区分三类问题：随机点是否漏掉某个目标部位、点的前后景标签是否判断错误，以及 SAM 是否把正确的点扩展成了错误区域。不能因为有多个前景点，就默认最终覆盖了全部目标。

## D：先分割，取各连通域中心点做判断

```text
原图 → SAM 自动候选 → 拆分各 mask 的连通域 → 每个连通域取一个内部中心点
     → 逐点标记并做 Noul 判断 → 每个预测前景点分别提示 SAM → 多个 mask 取并集
```

这是 A 与 C 的融合：用 A 的分割结果来安排采样点，再沿用 C 的点级前后景判断。相比 C 的均匀随机采样，点的位置由候选区域决定，目的是减少随机漏采；是否能更好地命中交互部位仍需测试。

初版按以下规则取点：

1. 复用 A 的候选生成与过滤配置，对每个候选 mask 按 8 邻域拆分连通域，每个非空连通域各取一个点。
2. 计算连通域所有像素坐标的均值作为几何中心，再选取该连通域内距离中心最近的像素作为实际点；并列时按固定的行、列顺序选取。**点必须落在连通域内部**，避免凹形或环形区域的中心落到背景。
3. 对重叠候选产生的完全相同坐标去重，保存每个点对应的候选编号与连通域编号。同图不同指令复用该点集，取点不读取 GT。

每次在完整原图上只标记一个点，使用与 C 相同的问题、Noul 阈值及前后景定义。一个点判断为前景，只说明该位置适合当前指令，**不能据此认定它所在的整个候选 mask 都有效**。因此 D 首版沿用 C 的后续流程：每个预测前景点分别配合预测背景点提示 SAM，再合并各次分割结果；不直接把该点所属的原始候选全部选中。没有可用中心点或没有预测前景点时，返回空 mask 并记录原因。

例如“抓住杯柄，把杯子拿起来”：如果候选中分出了杯柄，其内部中心点就能进入判断；如果只有整只杯子的候选，而中心点落在杯身，D 仍可能漏掉杯柄。D 的效果取决于候选是否包含合适的部件，以及中心点能否代表所需交互位置，不能保证优于 C。

D 的点数 P 由候选连通域数量及坐标去重结果决定，不固定为 32。比较选点方式时，可额外让 C 随机采样同样的 P 个点，并保持判断和后续分割设置一致；D 额外的自动候选生成成本也要计入。

## 先用少量样本比较

先准备 **5 条调试样本 + 20 条固定检查样本**，A、C、D 使用同一份清单，按实现进度逐步加入比较。首轮使用已下载的 UMD Tools，补充固定指令模板；检查清单中加入少量 Clutter 多区域样本。调试与检查两组按工具实例或场景分开，避免相邻视角混入两组。后续再用 ReasonAff 检查复杂指令，数据入口及版本问题见 [01](01_affordance_primer.md)。

首批同时包含单区域和多区域目标，按标注定义区分动作功能部位与手接触部位。UMD 的类别标签可能同时覆盖多个物体；若指令指定某个实例，必须有与之对应的 GT，不能直接把该类别的全部像素当答案。Clutter 中发现的 `-1` 标签需要先核对含义，明确有效像素规则后再计算指标。另选几组同图不同指令的例子，观察预测是否随任务变化；自写指令单独记录。

| 看什么 | A | C、D |
| --- | --- | --- |
| 最终质量 | 合并 mask 与 GT 的 IoU，同时看像素级精确率、召回率 | 同样计算；空预测也计入 |
| 前面的步骤是否提供了足够信息 | 全部候选并集覆盖了多少 GT 像素 | 随机点或连通域中心点是否命中各个分离的 GT 区域，命中多少点 |
| 模型判断是否正确 | 检查哪些候选被接受或拒绝，以及合并后的漏检与误检 | 前景/背景点误判数分开统计，避免大量背景点掩盖错误 |
| 对指令是否敏感 | 同图换指令后的保留候选集合与预测变化 | 固定点集下，标签与预测变化 |
| 总成本 | 候选生成、渲染、决策、输出耗时与请求数 | 选点、渲染、决策、最终分割耗时与请求数；D 另计自动候选生成耗时 |

GT 只用于离线评估，不能参与候选过滤、点采样或点标签预测。A 的候选覆盖率为 `|GT ∩ (∪ M_i)| / |GT|`，只检查是否遗漏目标像素；即使覆盖率高，候选也可能混入大量背景。原来的 `max_i IoU(M_i, GT)` 只衡量最佳单个候选，不再作为多区域输出的性能上限。

记录 A 的候选数 K、C 的随机点数 N、D 的中心点数 P，以及保留区域数、预测前景点数、SAM 分割调用数、分辨率与全部调用耗时。三种流程的决策次数和分割成本不同；即使 C、D 点数相同，也不能直接宣称是等计算预算实验。候选缓存后的耗时与首次完整流程耗时分开记录，模型加载和预热时间单列。

## 最小程序留下什么

拟逐步实现一个命令行入口，通过 A、C、D 模式切换，B 不实现。每条样本保存：

- 实际输入图：逐区域高亮图或逐点标记图。
- 中间结果：A 的全部候选 mask、编号映射和保留候选集合；C 的随机种子、坐标、预测标签和每次分割的 mask。
- D 额外保存：自动候选 mask、连通域划分、中心点坐标及其来源映射，以及点预测标签和每次分割的 mask。
- `scores.json`：原始模型响应、使用的分数与阈值、判定结果和各阶段耗时。
- `prediction.png` 与 `comparison.png`：合并后的最终二值 mask，以及原图、预测和 GT 的对照。

每次运行保存模型 revision、提示模板、候选与采样配置、设备和精度。**每种方式的最小完成标准是能输出单区域及多区域结果，并能从固定样本判断失败发生在候选覆盖、区域判断、选点、点判断还是分割与合并。**

## 附：SystemOneModel/Jev四种决策接口的直观例子

下面用一张带杯子的照片说明 Jev 的 Choice、Noul、Score 和 Box。**概率、坐标和响应片段都是简化示意，不是实际运行结果，也不是完整 API 请求。** 首版使用的 Valen-4B 有自己的请求与响应格式，接入时以其官方文档为准；其中 Box 是 Jev 1.14 的接口，不能据此假定 Valen-4B 也支持 Box。

### Choice：从候选区域中选一个

在图片上标出候选区域 A、B、C，给模型以下信息：

```text
任务：抓住杯柄，把杯子拿起来。
问题：应该选择哪个区域？
候选：A、B、C、都不合适。
```

输出示意：

```json
{
  "choice": "B",
  "probabilities": {
    "A": 0.05,
    "B": 0.85,
    "C": 0.08,
    "none": 0.02
  }
}
```

程序据此取出 B 对应的候选 mask。Choice 适合一次比较多个候选，其选项概率之和为 1；选择 `none` 时应由程序返回无合适区域。这个例子说明单选接口，不作为本轮多区域预测的实现方案；这里的 A、B、C 是候选编号。[Jev Choice 文档](https://docs.typesafe.ai/primitives/choice)

### Noul：独立判断每个区域是否适合

每次只在照片中高亮一个候选区域：

```text
任务：抓住杯柄，把杯子拿起来。
问题：高亮区域是否是这条指令要求抓取的部位？
```

输出示意：

```json
{"noul": 0.92}
```

表示模型给“是”分配了 0.92 的概率。分别询问三个候选，可能得到：

```text
区域 A：0.12
区域 B：0.92
区域 C：0.23
```

这些是独立判断，**不要求相加等于 1**，多个区域可以同时得高分。方式 A 采用这种思路，保留所有达到阈值的候选并合并 mask；以上例和 0.5 阈值为例，只保留 B，若其他候选也达到阈值，则一并保留。[Jev Noul 文档](https://docs.typesafe.ai/primitives/noul)

### Score：按有序等级评价操作进度

输入机器人操作杯子的当前照片，定义明确的等级：

```text
问题：当前操作进行到哪一步？
等级 0：尚未握住杯子。
等级 1：已经握住，但杯子仍接触桌面。
等级 2：已经把杯子抬离桌面。
```

输出示意：

```json
{
  "score": 1.75,
  "probabilities": {
    "0": 0.05,
    "1": 0.15,
    "2": 0.80
  }
}
```

`1.75 = 0×0.05 + 1×0.15 + 2×0.80`，表示判断更偏向“已经拿起来”。它是等级编号的加权分数，**不代表任务完成了 87.5%**。这个例子用于理解状态评价，与选择交互区域是不同问题。[Jev Score 文档](https://docs.typesafe.ai/primitives/score)

### Box：直接定位图像目标

输入原始照片，直接要求“定位照片中的杯柄”，不预先提供候选区域。

输出示意：

```json
{
  "box": {
    "left": 0.60,
    "top": 0.30,
    "right": 0.82,
    "bottom": 0.65
  }
}
```

坐标是相对图像宽高的比例。例如图像宽度为 1000 像素，左右边界对应 600 和 820 像素。Box 输出矩形框；如需精细 mask，可以把框交给 SAM 等分割模型。它需要 Jev 1.14，并开启实验性图像功能。Box 本身没有“未找到”输出，目标可能不存在时，需要另外询问 Noul 来判断目标是否存在。[Jev Box 文档](https://docs.typesafe.ai/primitives/box)
