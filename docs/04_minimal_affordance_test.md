# 最小 Affordance 决策测试

创建日期：2026-10-15。状态：方案草案，尚未实现或运行。

我们先验证：**输入图像与指令，视觉 System One 模型能否通过区域选择或前后景判断，得到正确的交互区域 mask？**

首轮集中比较下面三种形式，使用预训练模型做离线、零样本推理。模型、候选数和采样点数都是初始设置。

## 三种形式

| 方式 | 输入给决策模型什么 | 模型输出 | 最终 mask 怎样得到 |
| --- | --- | --- | --- |
| A：逐个高亮区域 | 全图分割后，每次在完整原图中高亮一个候选，加上指令 | 每个候选的 Noul 分数 | 取最高分候选的原始 mask |
| B：全部区域编号 | 全图分割后，在一张原图上标出全部候选及编号，加上指令 | Choice 选择的编号与候选概率 | 取该编号对应的原始 mask |
| C：随机点判断 | 在完整原图的随机位置逐次标点，加上指令 | 每个点属于目标前景的 Noul 分数 | 将预测的前景、背景点一起交给 SAM，生成 mask |

A、B 的“全图分割”指自动生成一组候选 mask；它们可能重叠或嵌套，并不要求形成互斥的语义分区。C 从图像采样点开始，最后才按点提示分割。

首版统一使用 **Valen-4B + SAM 2.1 small**：决策模型为 `Valen-Team/Valen-4B`，用于 A、C 的 Noul 二分类判断和 B 的 Choice 候选选择；SAM 为 A、B 生成自动候选，为 C 接收点提示。三种方式均输出与原图同尺寸的二值 mask。[SAM 2 官方仓库](https://github.com/facebookresearch/sam2)、[Valen 仓库](https://github.com/Liuziyu77/Valen)、[Valen-4B 模型卡](https://huggingface.co/Valen-Team/Valen-4B)

## A：先分割，逐个高亮判断

```text
原图 → SAM 自动候选 → 逐个高亮 → Noul 判断 → 最高分候选 mask
```

候选生成只读取图像，去掉空掩码与高度重复掩码，暂定最多保留 24 个。保存 mask、编号和过滤参数，小部件不能仅因面积小就被全部丢弃。A、B 必须使用完全相同的候选集合；同图不同指令也复用该集合。

每次在完整原图上以半透明青色和轮廓标出一个候选，透明度先固定为 0.25。问题示意：

```text
任务：{instruction}
高亮区域是否准确对应完成这条指令所需交互的功能部位？
```

读取 Noul 的 true 分数，按最高分选出一个候选；保留全部分数和原始响应。它们用于排序，尚不能当作已在 Affordance 上校准的成功概率。

有 K 个候选时，首版产生 K 张高亮图并逐个判断。若候选集合为空，返回空 mask 并记录原因。

## B：先分割，全部候选一次编号选择

```text
原图 → 同一组 SAM 候选 → 一张编号图 → Choice 选择 → 对应候选 mask
```

在同一张原图上，用不同颜色轮廓标出全部候选，并标注 1 至 K 的编号。保持原图纹理可见，编号锚点落在对应 mask 内；标签拥挤时可以用引线标明对应关系。重叠区域仍保留各自候选身份，保存编号与原始 mask 的映射。

问题与选项示意：

```text
任务：{instruction}
图中哪个编号的区域最准确地对应这条指令要求交互的功能部位？
候选：1、2、3、……、K。
```

Choice 的每个选项都写明“图中编号 X 的区域”，不给“杯柄”等额外语义提示。模型一次接收整张编号图和全部候选，程序根据返回编号取出 mask。

为便于比较，首版 A、B 都采用单选输出；候选均不理想的情况通过下文的候选上限识别。附录中的 none 是通用接口示例，暂不加入本轮 A、B 的对照。

B 减少了逐个提交高亮图的请求数，但候选多时编号与边界更难辨认；是否更快、选得更准，都要实际测量。

## C：随机给点，判断前后景后分割

```text
原图 → 随机采样点 → 逐点标记并判断 → 前景/背景点集合 → SAM mask
```

先在整张图中均匀随机采样 32 个不重复的像素位置，保存随机种子和原图坐标。同一张图使用固定点集，不根据 GT 或模型结果重新挑点。

首版每次只画一个小空心标记，让标记中心对应待判断像素，尽量保留该位置的视觉细节。完整原图与指令一起输入模型，提问：

```text
任务：{instruction}
标记中心的位置，是否属于这条指令对应的目标交互部位？
```

**这里的前景是指令指定的交互区域。** 例如指令要求抓杯柄，杯柄是前景，杯身、桌面等都可以是背景；判断“这个点是否在杯子上”不够准确。

读取每个点的 Noul true 分数。初始规则固定为：分数不低于 0.5 标为前景，其余标为背景；0.5 只是起始阈值，需要在调试样本上检查，检查集运行前冻结。

把全部点的原图坐标与预测标签传给 SAM，同时给 SAM **未经标记的原始图像**。使用前景标签 1、背景标签 0，并先采用单 mask 输出。若没有预测前景点，则返回空 mask、记录该情况，不强行把最高分点当成前景。[SAM 点提示接口](https://github.com/facebookresearch/sam2/blob/main/sam2/sam2_image_predictor.py)

C 的两个主要问题是：随机点可能完全没命中细小部位，错误点标签也可能让 SAM 分错区域。两种原因需要在结果里分开看。

## 先用少量样本比较

先准备 **5 条调试样本 + 20 条固定检查样本**，两组图像互不重叠，A、B、C 跑同一份清单。优先使用 ReasonAff 的图像、指令与 GT mask，数据入口及版本问题见 [01](01_affordance_primer.md)。数据暂不可用时，可先用明确标注的自建诊断集跑通。

首批选择存在明确目标交互部位的样本，按标注定义区分动作功能部位与手接触部位。另选几组同图不同指令的例子，观察预测是否随任务变化；自写指令单独记录。

| 看什么 | A、B | C |
| --- | --- | --- |
| 最终质量 | 预测 mask 与 GT 的 IoU | 同样计算 IoU；空预测也计入 |
| 前面的步骤是否提供了足够信息 | 候选上限：`max_i IoU(M_i, GT)` | 采样点是否命中 GT，命中多少点 |
| 模型判断是否正确 | 实际选择与候选上限之间的差距；随机选候选的期望 IoU 作参照 | 前景/背景点误判数分开统计，避免大量背景点掩盖错误 |
| 对指令是否敏感 | 同图换指令后的编号与预测变化 | 固定点集下，标签与预测变化 |
| 总成本 | 候选生成、渲染、决策、输出耗时与请求数 | 点采样、渲染、决策、最终分割耗时与请求数 |

GT 只用于离线评估，不能参与候选过滤、点采样或点标签预测。A、B 的候选上限不适用于 C。

记录实际 K、N、分辨率与全部调用耗时。A、B 的 K 和 C 的 N 不同，因此这是三套流程的初步比较，不能直接宣称是等计算预算实验。候选缓存后的耗时与首次完整流程耗时分开记录，模型加载和预热时间单列。

## 最小程序留下什么

拟实现一个命令行入口，通过 A、B、C 模式切换。每条样本保存：

- 实际输入图：逐区域高亮图、全部区域编号图或逐点标记图。
- 中间结果：A、B 的候选 mask 和编号映射；C 的随机种子、坐标与预测标签。
- `scores.json`：原始模型响应、使用的分数、选择结果和各阶段耗时。
- `prediction.png` 与 `comparison.png`：最终二值 mask，以及原图、预测和 GT 的对照。

每次运行保存模型 revision、提示模板、候选与采样配置、设备和精度。**第一轮完成标准是三种方式均能跑通，并能从固定样本判断失败发生在候选覆盖、编号选择、点采样、点判断还是最终分割。**

## 附：SystemOneModel/Jev四种决策接口的直观例子

下面用一张带杯子的照片说明 Jev 的 Choice、Noul、Score 和 Box。**概率、坐标和响应片段都是简化示意，不是实际运行结果，也不是完整 API 请求。** 首版使用的 Valen-4B 有自己的请求与响应格式，接入时以其官方文档为准；其中 Box 是 Jev 1.14 的接口，不能据此假定 Valen-4B 也支持 Box。

### Choice：从候选区域中选一个

在图片上标出候选区域 A、B、C，给模型以下信息：

```text
任务：抓住杯柄，把杯子拿起来。
问题：应该选择哪个区域？
候选：A、B、C、都不合适。
```

输出示意：

```json
{
  "choice": "B",
  "probabilities": {
    "A": 0.05,
    "B": 0.85,
    "C": 0.08,
    "none": 0.02
  }
}
```

程序据此取出 B 对应的候选 mask。Choice 适合一次比较多个候选，其选项概率之和为 1；选择 `none` 时应由程序返回无合适区域。[Jev Choice 文档](https://docs.typesafe.ai/primitives/choice)

### Noul：独立判断每个区域是否适合

每次只在照片中高亮一个候选区域：

```text
任务：抓住杯柄，把杯子拿起来。
问题：高亮区域是否是这条指令要求抓取的部位？
```

输出示意：

```json
{"noul": 0.92}
```

表示模型给“是”分配了 0.92 的概率。分别询问三个候选，可能得到：

```text
区域 A：0.12
区域 B：0.92
区域 C：0.23
```

这些是独立判断，**不要求相加等于 1**，多个区域可以同时得高分。方式 A 采用这种思路，再按最高分选出一个 mask；是否采用阈值或保留多个区域，属于后续输出规则。[Jev Noul 文档](https://docs.typesafe.ai/primitives/noul)

### Score：按有序等级评价操作进度

输入机器人操作杯子的当前照片，定义明确的等级：

```text
问题：当前操作进行到哪一步？
等级 0：尚未握住杯子。
等级 1：已经握住，但杯子仍接触桌面。
等级 2：已经把杯子抬离桌面。
```

输出示意：

```json
{
  "score": 1.75,
  "probabilities": {
    "0": 0.05,
    "1": 0.15,
    "2": 0.80
  }
}
```

`1.75 = 0×0.05 + 1×0.15 + 2×0.80`，表示判断更偏向“已经拿起来”。它是等级编号的加权分数，**不代表任务完成了 87.5%**。这个例子用于理解状态评价，与选择交互区域是不同问题。[Jev Score 文档](https://docs.typesafe.ai/primitives/score)

### Box：直接定位图像目标

输入原始照片，直接要求“定位照片中的杯柄”，不预先提供候选区域。

输出示意：

```json
{
  "box": {
    "left": 0.60,
    "top": 0.30,
    "right": 0.82,
    "bottom": 0.65
  }
}
```

坐标是相对图像宽高的比例。例如图像宽度为 1000 像素，左右边界对应 600 和 820 像素。Box 输出矩形框；如需精细 mask，可以把框交给 SAM 等分割模型。它需要 Jev 1.14，并开启实验性图像功能。Box 本身没有“未找到”输出，目标可能不存在时，需要另外询问 Noul 来判断目标是否存在。[Jev Box 文档](https://docs.typesafe.ai/primitives/box)
